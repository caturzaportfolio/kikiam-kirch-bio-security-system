# BIO-003 — DNN Recognition Hardening

## Purpose

BIO-003 replaces the BIO-002 Haar + LBP research baseline with OpenCV YuNet face detection and SFace embeddings. It keeps the Windows GUI, mirrored preview, local-only person registry, and no-raw-frame persistence behavior.

## Why this wave exists

Target-laptop testing showed that BIO-002 could enroll and persist people, but the LBP matcher produced roughly 0.68 similarity for the same enrolled face while the research threshold was 0.86. BIO-003 fixes the recognition backend instead of weakening the threshold.

## Runtime behavior

On first `bio-security gui --camera 0` launch, the app downloads two official OpenCV Zoo ONNX models into the per-user Kikiam model directory, then verifies the exact upstream SHA-256 and file size before loading them.

- YuNet: `face_detection_yunet_2023mar.onnx`
- SFace: `face_recognition_sface_2021dec.onnx`

BIO-003 uses a separate `registry_sface.sqlite3` by default because BIO-002 LBP templates are mathematically incompatible with SFace embeddings. Existing BIO-002 records remain untouched. Test people must be enrolled again once under BIO-003.

## Recognition policy

- YuNet detection score threshold: 0.90
- SFace cosine match threshold: 0.45 by default
- stable MATCH requires the same identity on at least 3 of the last 5 observations
- multiple visible faces suppress the global identity panel
- duplicate biometric enrollment is blocked at a stricter 0.55 similarity threshold

OpenCV documents 0.363 cosine similarity as an example same-identity threshold on LFW for SFace. BIO-003 starts more conservatively at 0.45 and requires temporal agreement; target-laptop evidence should be used before changing it.

## Windows test

```powershell
cd "$HOME\Projects\kikiam-kirch-bio-security-system"
git fetch --all
git checkout KIKIAM-BIO-003-DNN-RECOGNITION-HARDENING
git pull
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\bio-security.exe gui --camera 0
```

The first launch may take longer while the ~37 MB SFace model is downloaded and verified.

## Acceptance evidence still required

1. Enroll one person once in the new BIO-003 registry.
2. Leave and re-enter the camera view and verify a stable MATCH.
3. Put an unenrolled person in view and verify UNKNOWN.
4. Attempt to enroll the same face under a second ID and verify duplicate enrollment is blocked.
5. Put two people in frame and verify the identity panel is suppressed until one face remains.
6. Confirm no raw camera frames are written to disk.

This remains a biometric research prototype, not a production physical-access decision system.
