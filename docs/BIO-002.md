# BIO-002 — GUI Enrollment and Local Recognition Baseline

## Status

Implementation candidate. Hardware acceptance is still required on the target Windows laptop.

## Scope

BIO-002 builds on the accepted BIO-001 camera/detection baseline and adds a local desktop GUI:

```text
Camera
  ↓
Face Detection
  ↓
┌──────────────────────┐
│ Tkinter Desktop GUI  │
├──────────────────────┤
│ Enroll Person        │
│ View People          │
│ Live Recognition     │
└──────────┬───────────┘
           ↓
Derived Face Template
           ↓
Local SQLite Registry
           ↓
MATCH / UNKNOWN
```

This is still a research/benchmark system. A recognition match is **not** an access-control decision.

## Windows launch

From the repository:

```powershell
git fetch --all
git checkout KIKIAM-BIO-002-GUI-ENROLLMENT-RECOGNITION

py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

.\.venv\Scripts\bio-security.exe gui --camera 0
```

The GUI uses Python's built-in Tkinter. The official Windows Python 3.12 installer normally includes Tk/Tcl support.

## Enrolling a person

Open **Enroll person**, enter:

- Employee / Person ID
- First name
- Last name
- Department
- Position

Choose **Start enrollment**. Keep exactly one face in the frame. The prototype captures eight derived samples by default, roughly one every 350 ms. Move slightly between samples.

The enrollment can also be configured from PowerShell:

```powershell
.\.venv\Scripts\bio-security.exe gui --camera 0 --samples 10
```

## Recognition

After enrollment, the application automatically reloads local templates. The live camera view compares detected faces against active enrolled templates and reports either:

```text
MATCH
UNKNOWN
```

For a match, the GUI displays the locally stored name, employee/person ID, department, position, and research similarity score.

The default matching threshold is `0.86`. It is deliberately configurable because BIO-002 has not yet produced a calibrated FAR/FRR threshold:

```powershell
.\.venv\Scripts\bio-security.exe gui --camera 0 --threshold 0.88
```

Do not interpret a threshold change as a security improvement without benchmark evidence.

## Local data

By default the registry is stored outside the repository:

```text
%LOCALAPPDATA%\KikiamBioSecurity\registry.sqlite3
```

The database contains person metadata and derived biometric templates. It does **not** store raw camera frames by default.

The registry is sensitive local data. Do not commit, email, publish, or copy it casually. This prototype does not yet implement encrypted-at-rest template storage or a managed key lifecycle.

A custom test registry can be used:

```powershell
.\.venv\Scripts\bio-security.exe gui --registry C:\KikiamTest\registry.sqlite3
```

## Biometric baseline

BIO-002 uses a Local Binary Pattern (LBP) feature extractor over the detected face crop and cosine template matching. Multiple enrollment templates are stored for each person and the strongest templates are aggregated during matching.

This is intentionally a lightweight local research baseline. It is **not** claimed to provide production-grade identity assurance and must not be treated as liveness/PAD.

## Non-goals

BIO-002 does not implement:

- door or lock control;
- automatic grant/deny decisions;
- liveness or presentation-attack detection;
- cloud biometric storage;
- public APIs;
- background surveillance;
- production identity assurance.

## Verification

Repository checks:

```powershell
.\.venv\Scripts\ruff.exe check src tests
.\.venv\Scripts\mypy.exe src
.\.venv\Scripts\pytest.exe
```

Hardware acceptance must additionally prove:

1. the Tkinter GUI launches on the target Windows laptop;
2. the real camera preview remains stable;
3. one person can be enrolled successfully;
4. the resulting registry contains the person and expected template count;
5. the same person can produce a stable MATCH under reasonable pose/lighting variation;
6. an unenrolled person remains UNKNOWN under the configured threshold;
7. multiple visible faces do not produce an access decision;
8. no raw camera frame is saved by default.

## Security boundary

`MATCH` means only that this research matcher found sufficient similarity to locally enrolled templates. It must remain separate from any future authentication or physical-access policy.
